Atomic care submission and admin diagnostics

Remote structured care submissions use append_owned_care_log, a SECURITY INVOKER
RPC that retains existing staff RLS and care-history protection. It locks the dog
then the daily source (the same order as admin corrections), appends only the new
entry to each daily history array and the matching dog history, and commits both
or neither. Earlier entries, duplicates, edit metadata, and unrelated fields are
preserved. Backdating does not move latest-care dates backwards. Repeated IDs by
the same actor return the durable entry; conflicting actors/identities are denied.
The frontend retains an opaque retry ID keyed by account and payload digest until
confirmation, deduplicates simultaneous clicks, and never falls back to replacing
a remote day's history from browser cache. Retry IDs contain no care-note payload.
All direct profile log buttons now await confirmation before showing success.

Admin location: Settings > Audit Log > Troubleshooting text log.
Diagnostics cover record-save and structured-care submission failures. They carry
operation, record/dog IDs, care type/date, server-attributed actor and timestamp,
error code, fixed sanitized message, and request ID if available. Raw error details,
stack, session, tokens, passwords, photos, and care notes are not recorded. Unknown
errors are generic. Client events are best-effort reports, not authoritative audit
proof; offline events can be lost. The UI explicitly labels these limitations.

Existing owner/admin/manager/staff members may insert. Only owner/admin members
may read, within the current organization. Clients cannot supply actor/time/org,
or update/delete events. Customer and anonymous access is denied. Daily pg_cron
cleanup removes events older than 14 days; actual removal can be up to one day
later. Only the diagnostic table is affected. No existing access policy changed.
